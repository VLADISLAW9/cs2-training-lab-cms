# cs2-training-lab-cms

Независимый сервис CS2 Learning Platform. Node.js 22, PostgreSQL 16. Фронтенд не входит в проект.

## Локальный запуск

```sh
cp .env.example .env
npm install
docker compose -f compose.json up -d
npm run develop
```

Заполните `.env` перед запуском. Секреты генерируйте через `openssl rand -hex 32`; не коммитьте `.env`.

После настройки `.env` запускайте `npm run dev`: команда поднимает отдельную базу CMS на порту 5434, дожидается её готовности и запускает Strapi в режиме разработки. Docker Desktop должен быть запущен.

## Production

```sh
npm install
npm run build
NODE_ENV=production npm start
```

Docker: `docker build -t cs2-training-lab-cms .`, затем `docker run --env-file .env -p 1337:1337 cs2-training-lab-cms`. PostgreSQL должен быть доступен по DATABASE_URL из контейнера; localhost указывает на сам контейнер. Выполните миграции Backend отдельной командой перед запуском. Используйте HTTPS reverse proxy; настройте TRUST_PROXY только на доверенные адреса прокси. Каждый сервис имеет отдельную базу и развёртывается самостоятельно. Compose поднимает только локальную базу этого сервиса.

## Настройка CMS и локального хранения

Откройте http://localhost:1337/admin и создайте первого администратора. Используется стандартная панель Strapi. Модели включают Draft & Publish; для публикации гранат нужны фотографии, для скриптов видео и обложка. Порядок images задаётся перетаскиванием в media field и сохраняется Strapi; первая фотография служит обложкой.

В Settings → API Tokens создайте Custom token: только find/findOne для Map, MapZone, Grenade, Script. Скопируйте его в STRAPI_API_TOKEN Backend. Не включайте права Public на контент. Токен и аккаунт администратора создаются при настройке окружения, секреты в репозитории отсутствуют.

Фотографии и видео хранятся локально в `public/uploads` через встроенный провайдер Strapi `local`. Загружайте их через Media Library или поля медиа в Content Manager. Файлы доступны по адресу `http://localhost:1337/uploads/<имя-файла>`. Backend преобразует относительные пути медиа в полные URL на основе STRAPI_URL. Ключи сторонних сервисов не нужны.

При деплое сохраняйте `public/uploads` между обновлениями и резервируйте эту папку вместе с PostgreSQL. Для Docker подключайте постоянный том: `-v cs2-cms-uploads:/app/public/uploads`. MP4 рекомендуется кодировать H.264/AAC с faststart; транскодирование не реализовано.

UPLOAD_MAX_BYTES ограничивает размер файла (по умолчанию 100 MiB). Разрешены JPEG, PNG, WebP, MP4. Лимит reverse proxy согласуйте с лимитом Strapi. Доступ администратора ограничьте на уровне инфраструктуры. Резервируйте PostgreSQL и папку `public/uploads`.

Slug материалов и зон проверяется в пределах карты. Поле slug использует строку с валидацией вместо глобально уникального Strapi UID, чтобы одинаковые slug могли существовать на разных картах. Все связи проверяются в транзакции Document Service. MIME ограничения настроены в `config/plugins.js`.

Зависимости ещё не установлены в исходной среде: npm registry недоступен. После первой установки сохраните package-lock.json и используйте npm ci в CI/Docker. Сборка и интеграционные проверки требуют доступных зависимостей и настроенных внешних сервисов.

## Ручная приёмка

1. Поднять базу, установить зависимости, собрать и запустить сервис.
2. Создать и опубликовать карту, зоны, гранату с двумя изображениями и скрипт с видео.
3. Проверить запрет публикации без медиа и связи с зонами/гранатами другой карты.
4. Проверить скрытие drafts и материалов неактивной карты через Backend.
5. Проверить смешанный каталог на нескольких страницах: общий порядок, total, отсутствие повторов; фильтры both и zone; 400 для page=0 и несовместимых параметров.
6. Пройти Steam login, проверить me, logout с Origin и отказ повторному callback.
7. Проверить прямые медиа URL и HTTP Range на CMS.

Автоматизированные тесты в объём работ не включены.
